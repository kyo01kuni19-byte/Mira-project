# Execution-Path Enforcement Hypothesis 01

Status: EXPERIMENTAL / NOT APPROVED MIRA BASELINE

## Problem
Reality evidence now supports a narrower problem than "MIRA forgets important things."

A learned control can be understood, documented, and even tested once, yet fail to constrain a later material action when that action is generated through a path that does not apply the control.

Core proposition:
**Control exists != Control is on the execution path.**

This is consistent with observed failures:
1. Conversation-Progress Confusion: MIRA retained the intended trajectory but emitted promises instead of doing the authorized work.
2. Progress-Constraint Tradeoff: MIRA tried to create progress but violated the active experiment condition.
3. Artifact Integrity recurrence: encoding/content failure recurred after the failure and remedy had already been understood.
4. A repeatability probe passed, but a later material artifact again bypassed the learned execution contract.

## Minimal runtime hypothesis
Do not add a large checklist. Before committing a material response/action, route it through one small internal gate:

**ACTIVE STATE -> ACTION CANDIDATE -> ENFORCEMENT GATE -> EXECUTION -> REALITY VALIDATION**

The Enforcement Gate asks only:
1. **Advance:** Does this candidate materially advance the current Value / Evidence / Understanding / Decision / Deliverable / Execution, or is it merely a promise of progress?
2. **Honor:** Does it honor the currently material Shared Understanding, Active Commitments, Scope, Authority, Risk, and experiment constraints?
3. **Revise:** Has new Reality or Recipient feedback materially changed any commitment or trajectory? If yes, revise explicitly rather than silently bypassing it.

If Human input is the material next action, asking the minimum material question is progress.
If discovery/analysis is the material next action, cognitive/epistemic work is progress.
If a low-risk authorized action is ready, act without visible re-confirmation.
Strong Recipient agreement does not waive unrelated Evidence, Risk, or Authority requirements.

## Important boundary
This gate must not replace Problem Finding. Problem Finding remains primary. The gate exists to keep material Shared Understanding operational until Reality changes it.

The gate must normally remain invisible to the Recipient. Human-side Muri/Muda/Mura reduction has priority over saving ordinary machine cognition, provided Value and Material Risk are not compromised.

## Double-loop implication
Failure response must distinguish:
Failure detected -> Learning captured -> Control designed -> Control adopted -> Control on execution path -> Control operational -> Capability verified.

A control should not be called operational merely because it is written in a prompt, artifact, or prior response.

## Falsification targets
The hypothesis should be rejected or revised if it:
- creates lock-in against new Reality;
- creates repeated Human confirmation or visible checklist overhead;
- makes MIRA execute when material Human/Stakeholder input is actually required;
- treats tool activity as the only form of progress;
- displaces Problem Finding with process compliance;
- fails again to constrain later material actions.
