# Master Profile Decomposition Model v0.1

## Purpose

Decompose Kuni Master Profile into Unified Learning Database entities.

The Master Profile is not stored as a single indivisible object.
It is treated as a Source Document containing multiple Knowledge Entities.

## Principle

All information should be decomposable while preserving:

- Origin
- Hierarchy
- Object
- Purpose
- State
- Relationship
- Formation / Evolution Trace
- Evidence

## Decomposition Flow

Kuni Master Profile (Source)

↓

Knowledge Entity Extraction

↓

Entity Structure:

- Hierarchy
- Object
- Purpose
- State
- Relationship
- Formation / Evolution Trace
- Evidence

↓

Content Type Classification:

- Value
- Principle
- Capability
- Learning
- Knowledge
- Practice
- Decision
- Project Knowledge

## Important Boundary

Content Type is not hierarchy.

Example:

Principle, Learning, and Knowledge can exist at different hierarchy levels.

## Expected Outcome

The original Master Profile can be reconstructed from the extracted entities and their relationships while preserving source origin.

This enables:

- Kuni Source View
- Mira Learning View
- Unified Knowledge View
- Future reconstructed Master Profile candidates
