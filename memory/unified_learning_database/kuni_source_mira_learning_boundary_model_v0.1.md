# Kuni Source → Mira Learning Boundary Model v0.1

## Purpose

Define the boundary between original Kuni Source information and Mira-generated structured learning inside the Unified Learning Database.

The purpose is not to replace the source document.
The purpose is to preserve origin while enabling reconstruction and reuse.

---

# 1. Source Layer

## Kuni Source

Original information explicitly created or provided by Kuni.

Examples:

- Kuni Master Profile
- Kuni Way principles
- Original hypotheses
- Original terminology

Characteristics:

- Preserved as origin
- Not rewritten as Mira conclusion
- Maintains creator context

---

# 2. Extraction Layer

## Extracted Knowledge Entity

Structured representation created from Source.

Transformation:

Kuni Source
↓
Entity Extraction
↓
Unified Learning Database Object

The extracted object preserves:

- Source location
- Original meaning
- Purpose
- Relationships
- Evidence

---

# 3. Mira Interpretation Layer

## Mira Inference

Interpretation created by analyzing Source and connecting evidence.

Examples:

- Common structure hypothesis
- Relationship discovery
- Cross-project pattern recognition

Mira Inference must remain distinguishable from Kuni Source.

---

# 4. Mira New Insight Layer

## New Insight

A hypothesis generated through interaction, validation, and learning.

Lifecycle candidate:

Observation
↓
Dialogue
↓
Hypothesis
↓
Validation
↓
Learning

A New Insight should not automatically become Principle.
It requires evidence and validation.

---

# 5. Unified Entity Representation

All layers can use the common structure:

Hierarchy
↓
Object
↓
Purpose
↓
State
↓
Relationship
↓
Formation / Evolution Trace
↓
Evidence

---

# 6. Boundary Rule

Never merge:

- Source and Interpretation
- Evidence and Assumption
- Learning and Established Principle
- Hypothesis and Validated Knowledge

Preserve transformation history.

---

# 7. Validation Status

Current hypothesis:

Kuni Source can be decomposed into reusable Knowledge Entities while preserving origin and allowing Mira capability reconstruction.

Further validation required:

- Automated extraction rules
- State transition model
- Confidence management
- Large-scale entity relationship handling
