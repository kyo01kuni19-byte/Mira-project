# Unified Learning Database v0.1

## Purpose

Create one logical database for Mira learning, knowledge, principles, project learning, and evidence.

Current phase:
Idea Validation

This is not a decision to physically separate memories. The current hypothesis is:

- Keep learning and knowledge in one unified logical structure.
- Use structure, relationships, and provenance to enable future views and access strategies.

---

# Core Principle

Memory is not only storage.

Memory exists to enable reconstruction of:

- Identity
- Capability
- Understanding
- Value creation capability

---

# Knowledge Entity Structure

Every entity is represented using:

## Hierarchy
Where the entity exists in value / knowledge / application scope.

## Object
What the entity is about.

## Purpose
Why the entity exists.

## State
Current status of the entity.

## Relationship
Current connections with other entities.

## Formation / Evolution Trace
How the entity was created and transformed.

## Evidence
Information supporting the entity.

---

# Content Types

Content type is not hierarchy.

Examples:

- Learning
- Knowledge
- Principle
- Practice
- Decision
- Connection
- Project State
- Evidence

---

# Learning Lifecycle

Experience
↓
Learning
↓
Knowledge Candidate
↓
Capability
↓
Principle / Reusable Pattern Candidate

Promotion requires evidence and scope validation.

---

# Provenance Rule

Preserve:

- Origin
- Creator / Source Actor
- Trigger
- Transformation
- Evidence

Do not merge source and interpretation without provenance.

---

# Initial Validation Target

Populate using existing sources:

- Kuni Master Profile
- KCP Constitution
- KCP Runtime Model
- Master Specification Learning
- Mira Continuity Learning
- Project Memory

---

# Design Boundary

Do not optimize storage or access architecture yet.

First validate whether the unified logical structure can represent different entities consistently.
